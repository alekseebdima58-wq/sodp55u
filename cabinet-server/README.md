# Синхронизация личного кабинета

Во вкладке PWA студент вводит логин и пароль ПривГУПС. Сервер отправляет обычную форму входа `newlk.samgups.ru/login` (поля `_token`, `login`, `password`, `remember=on`) простым HTTP-запросом, без браузера. После входа сохраняются только cookie сайта, а в PWA — ключ доступа конкретного устройства. Пароль нигде не хранится. При повторном входе приложение проверяет, что открыта та же зачётная книжка. Если сайт вуза запрашивает дополнительную проверку (капча, код), нужен обычный вход на сайте.

## Как устроено чтение кабинета

Сайт вуза — Laravel с Livewire 2 и Alpine.js.

- Сессия сайта (`licnyi_kabinet_studenta_session`) живёт 2 часа. Обновлять кабинет позже позволяет cookie «Запомнить меня» (`remember_web_…`): Laravel по нему сам открывает новую сессию, и сервер сохраняет её cookie.
- Зачётка (`/student/book/list`) — все курсы уже в HTML, их переключает Alpine.
- «Моя группа» — вкладка Alpine на `/dashboard`, список уже в HTML. Сохраняются все столбцы таблицы (ФИО, день рождения и т. п.) для карточки одногруппника — это личные данные группы; видит их только сам студент по своему ключу.
- Приказы, учебный план, профиль — по одной странице.
- Сессия (`/schedule/students/list`) — компонент Livewire `schedule-student-main` держит события месяца готовым списком в `serverMemo.data.events`. Сервер берёт текущий и два следующих месяца (метод `addMonth`) и оставляет только экзамены, зачёты и консультации. Фильтры расписания на сайте не меняются.
- Траектория (`/student/trajectory`) — открытый семестр в HTML, остальные — через Livewire: `selectSemester` у `trajectory-semesters` → событие `select-semester` у `trajectory` → четыре события у `trajectory-semester-disciplines`. Сервер повторяет эту цепочку запросами `/livewire/message/…`, как `livewire.js` в браузере.
- HTML разбирается библиотекой `linkedom`.

Если студент нажмёт «Выход» на сайте вуза, Laravel сбрасывает «Запомнить меня» на всех устройствах. Следующее обновление получит статус `expired`, и PWA попросит войти снова.

## Уведомления

Новые оценки и изменения сессии приходят тем же путём, что изменения расписания: через бота, push на телефон или сообщение в Telegram, по переключателю «Изменения». Приложение передаёт серверу (`POST /cabinet/v1/notify`) метку — HMAC личного ключа уведомлений со словом `cabinet` — и адрес канала бота из `data/index.json`. Сам личный ключ сервер не получает. После каждого обновления сервер сравнивает зачётку и сессию с прошлой копией и кладёт в канал зашифрованное подписанное сообщение `{q: "cab", …}`; бот находит по метке чат и рассылает. Канал разрешён только на хостах из `CABINET_RELAY_HOSTS` (по умолчанию `ntfy.sh`). Протокол описан в `notify.mjs`.

## Развёртывание

Нужен Node.js 22 или новее. Выполняйте команды из `cabinet-server` под отдельным непривилегированным пользователем.

```sh
npm install --omit=dev
CABINET_PWA_ORIGIN=https://alekseebdima58-wq.github.io node server.mjs serve
```

Chromium на сервере больше не нужен.

Укажите фактический origin PWA, включая схему и без пути. Несколько разрешённых origin можно перечислить через запятую. Сервис слушает `127.0.0.1:8776`. Через доверенный HTTPS-прокси направьте `/cabinet/v1/login`, `/cabinet/v1/snapshot`, `/cabinet/v1/refresh` и `/cabinet/v1/notify` на этот адрес. Передавайте заголовки `Origin` и `Authorization`. Не записывайте тела запросов и заголовки `Authorization` в журналы прокси или приложения.

В `cabinet-config.json` в корне PWA укажите публичный HTTPS-адрес этого сервиса в поле `server`. Оставьте адрес пустым до развёртывания. После входа сервер сразу ставит кабинет в очередь на обновление. Дальнейшие обращения к ПривГУПС происходят раз в 3 дня для каждого подключения, а в декабре и январе (зимняя сессия) — каждые 4 часа. Сервер каждые пять минут проверяет срок по сохранённой дате последней попытки. Обновление свайпом в PWA (`POST /cabinet/v1/refresh`) просит сервер сразу забрать свежие данные с сайта вуза — каждый раз, без ограничения по времени; пока обновление идёт, повторный запрос не запускает второе. Приложение ждёт новую копию через `/cabinet/v1/snapshot`.

Сессии и сохранённые данные находятся в `~/.local/state/sodp55u-cabinet`. Путь можно задать через `CABINET_STATE_DIR`. Храните каталог вне репозитория и раздачи статических файлов. Доступ к нему даёт доступ к сохранённым сессиям и студенческим данным: cookie «Запомнить меня» действует как вход в кабинет студента.

Кнопка «Отключить» в PWA удаляет локальный ключ. Для отзыва ключа и удаления его сохранённой сессии и данных на сервере используйте `node server.mjs disable <идентификатор>`.

## Проверка

```sh
npm install
npx playwright install chromium
npm test
```

Тесты используют макет портала (`mock-portal.mjs`), повторяющий настоящий сайт: форму с `_token`, ответ 302, cookie сессии и «Запомнить меня», цепочку Livewire траектории. Они проверяют вход, неверный пароль, дополнительную проверку, вход по «Запомнить меня» после истечения сессии, выход на сайте вуза, изоляцию данных двух студентов и все разделы в PWA.

`CABINET_PARSER=chromium npm test` разбирает страницы в Chromium вместо `linkedom` — для сверки, что разбор не зависит от библиотеки. `CABINET_CHROMIUM_PATH` задаёт свой Chromium для тестов.

## Проверки на GitHub

`.github/workflows/cabinet.yml` запускает тесты при каждом изменении сервера, `cabinet.js`, `cabinet.css` или `index.html` — дважды: с `linkedom`, как на сервере, и с разбором в Chromium. Скриншоты кабинета в PWA сохраняются в артефакт `cabinet-screens`.

Проверка на настоящем сайте — вручную: Actions → «Кабинет — проверки» → Run workflow → отметить «Войти на настоящий newlk.samgups.ru». Нужны секреты репозитория `LK_LOGIN` и `LK_PASSWORD`. Скрипт `live-check.mjs` печатает только количество строк по разделам.

То же на своём сервере, без сохранения пароля в истории команд:

```sh
read -p 'Логин: ' LK_LOGIN; read -s -p 'Пароль: ' LK_PASSWORD; echo
LK_LOGIN="$LK_LOGIN" LK_PASSWORD="$LK_PASSWORD" node live-check.mjs
```

## Повтор после ошибки и ограничение входа

Если сайт ПривГУПС не ответил или прочитались не все разделы, сервер не ждёт обычного срока. Он повторяет попытку через 15 минут, затем через 30, 60, 120 и 240 минут, но не реже обычного интервала. Счётчик неудач подряд хранится в сессии (`failures`) и сбрасывается после полного обновления. Истёкший вход не повторяется: нужен новый вход в приложении.

Вход (`POST /cabinet/v1/login`) ограничен, чтобы вуз не заблокировал адрес сервера из-за неверных паролей:
- не больше 2 входов одновременно и не два входа одного логина сразу;
- 5 неверных паролей для логина за 15 минут — этот логин ждёт 15 минут;
- 10 неверных паролей по всем логинам за 15 минут — вход для всех на паузе 15 минут;
- не больше 30 попыток за 5 минут.

Ошибки самого сайта вуза в неудачи не считаются. Удачный вход обнуляет неудачи логина. Ответ при блокировке: `429 {"error":"rate_limited","retryAfter":<секунды>}`.

## Проверка на настоящем сайте

`LK_LOGIN=… LK_PASSWORD=… node live-check.mjs` печатает число строк по разделам, заполненность столбцов группы и виды событий расписания на 6 месяцев вперёд (вид, код, цвет — без дисциплин и дат). Пометка `[сессия]` показывает, какие события попадают в раздел «Сессия». Если вуз опубликовал экзамены, а пометки нет — пришлите этот список.

## Сессия без ручной проверки

Раздел «Сессия» сервер заполняет сам при каждом обновлении. Экзаменом считается событие, которое отметил фильтр сайта «Экзамены (зачеты)» (если он есть в «Списке» или «Сетке» расписания и действительно меняет выдачу), или событие с видом, цветом или кодом экзамена, зачёта, консультации или аттестации. Фильтр сервер проверяет на том же месяце до и после включения: если галочка ничего не изменила, ею не пользуется, чтобы обычные пары не попали в сессию.
